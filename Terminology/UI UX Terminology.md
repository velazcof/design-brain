

|Term|Meaning|Example / Why it matters|
|---|---|---|
|**Semantics**|The meaning or role something has, rather than just how it looks.|A `<nav>` is semantically navigation; `color-primary-action` is named by purpose rather than by appearance.|
|**Token**|A named design value used consistently across a design system.|`spacing-md = 16px`, `color-blue-500 = #3B82F6`. Similar to a variable in code.|
|**Semantic Token**|A token named by its intended role rather than its raw value.|`color-text-muted` instead of `gray-500`; `surface-danger` instead of `red-100`.|
|**Design System**|A shared set of rules, components, styles, tokens, and patterns used to build consistent products.|Buttons, typography scales, spacing rules, colors, form patterns, etc.|
|**Component**|A reusable piece of interface.|Button, card, navbar, modal, stepper.|
|**Pattern**|A repeatable solution to a common UX problem.|Wizard, infinite scroll, checkout flow, search + filters.|
|**Surface**|A visually distinct layer or area that content sits on.|Page background, card background, modal surface.|
|**Gutter**|Space between columns or major layout regions.|A 24px gap between two grid columns.|
|**Margin**|Space outside an element.|Space separating a section from the next section.|
|**Padding**|Space inside an element, between its content and boundary.|A card with `24px` padding around its text.|
|**Gap**|Space between child elements in a layout.|`gap: 16px` between cards in a flex or grid container.|
|**Grid**|A layout structure made from columns, rows, and gutters.|A 12-column desktop layout.|
|**Column**|A vertical division in a grid.|A content area spanning 8 of 12 columns.|
|**Breakpoint**|A viewport width where the layout changes responsively.|Switching from two columns to one column on mobile.|
|**Responsive Design**|Designing interfaces that adapt to different screen sizes.|Navigation collapsing into a mobile menu.|
|**Hierarchy**|The visual ordering of importance.|Hero heading → supporting text → metadata.|
|**Visual Weight**|How strongly an element attracts attention.|A large bold button has more visual weight than muted text.|
|**Contrast**|The visual difference between elements.|Dark text on a light background; bright CTA on a neutral page.|
|**Luminance**|The perceived brightness of a color.|Used when calculating accessibility contrast ratios.|
|**Saturation**|How vivid or gray a color appears.|Highly saturated red feels more intense than a muted red.|
|**Chroma**|A measure of color intensity, commonly used in spaces such as OKLCH.|Increasing chroma makes a color appear more colorful.|
|**Affordance**|A visual clue suggesting how something can be used.|A raised-looking button suggests it can be clicked.|
|**Signifier**|A visible cue that communicates an affordance.|An underline tells you text is a link.|
|**CTA**|Call to action — an element encouraging the user to take an important action.|“View Projects”, “Buy Now”, “Create Account”.|
|**Hero**|The prominent introductory section near the top of a page.|Name, role, short description, and CTA on a portfolio homepage.|
|**Above the Fold**|Content visible before the user scrolls.|The hero and primary navigation are often above the fold.|
|**Whitespace**|Intentional empty space around elements.|Large spacing around a headline can increase emphasis and clarity.|
|**Alignment**|Positioning elements along shared visual lines.|Headings and body copy sharing the same left edge.|
|**Baseline**|The invisible line that text characters sit on.|Used to align text from different components or font sizes.|
|**Rhythm**|Repeated spacing or visual patterns that make a layout feel consistent.|Consistent 8px-based spacing across a page.|
|**Density**|How much information or UI is packed into a space.|A dashboard is often denser than a marketing page.|
|**State**|A visual or behavioural condition of a component.|Default, hover, focus, disabled, loading, error.|
|**Focus State**|A visual indication of which interactive element currently has keyboard focus.|A visible outline around a focused button.|
|**Hover State**|The appearance of an element when the pointer is over it.|A button becoming slightly brighter on hover.|
|**Disabled State**|A state indicating an action is currently unavailable.|A grayed-out submit button.|
|**Empty State**|UI shown when there is no content or data yet.|“No projects found” with guidance for what to do next.|
|**Feedback**|A response from the interface confirming the result of an action.|Success message after saving a form.|
|**Microinteraction**|A small interaction or animation that communicates state or feedback.|A heart icon animating after being liked.|
|**Progressive Disclosure**|Showing information only when it becomes relevant.|Advanced settings hidden behind an expandable section.|
|**Stepper**|A component showing progress through multiple steps.|`Account → Details → Confirm`.|
|**Wizard**|A multi-step workflow that guides the user through a process.|Account setup, onboarding, checkout.|
|**Modal**|A temporary layer that appears above the current interface and demands attention.|Confirmation dialog before deleting something.|
|**Overlay**|A visual layer placed over existing content.|The dimmed background behind a modal.|
|**Tooltip**|A small contextual label or explanation, usually shown on hover or focus.|Hovering an icon reveals “Share”.|
|**Popover**|A floating panel anchored to another UI element.|Clicking a profile icon opens account actions.|
|**Navigation**|The system users use to move through an interface.|Navbar, sidebar, breadcrumbs.|
|**Breadcrumbs**|A navigation trail showing the user's location in a hierarchy.|`Home / Projects / Portfolio`.|
|**Information Architecture (IA)**|How information is grouped, labelled, and structured across a product.|Deciding which pages belong under Account vs Settings.|
|**User Flow**|The sequence of steps a user takes to achieve a goal.|Landing page → project → contact form → confirmation.|
|**Wireframe**|A low-detail representation of a layout focused on structure.|Gray boxes showing where hero, projects, and footer go.|
|**Mockup**|A more visually detailed representation of the final design.|A polished Figma screen with colors and typography.|
|**Prototype**|An interactive representation used to test how a design behaves.|Clicking “Next” in Figma moves to another screen.|
|**Fidelity**|How closely a design representation resembles the final product.|Sketch = low fidelity; polished interactive mockup = high fidelity.|
|**Accessibility (a11y)**|Designing so people with different abilities can use the product.|Keyboard navigation, readable contrast, screen-reader support.|
|**WCAG**|Web Content Accessibility Guidelines.|WCAG 2.2 AA includes common accessibility requirements such as text contrast.|
|**Design Language**|The consistent visual and behavioural character of a product.|Shared typography, spacing, colors, motion, and component styling.|
|**Visual Language**|The visual conventions used to communicate meaning.|Blue = links, red = destructive actions, muted text = lower priority.|
